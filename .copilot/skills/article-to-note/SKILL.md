# Article to Note

將技術文章整理成一份結構清晰的繁體中文學習筆記，讓你日後複習時不需重讀原文。

## 執行步驟

### Step 1 — 讀取文章

取得文章來源（優先順序）：
1. 對話中被 tagged 的 `.md` 檔
2. 使用者貼上的文字內容
3. 使用者提供的 URL（用 fetch 取得）

---

### Step 2 — 判斷領域，決定評論專家身份

閱讀文章後，依主題對照下表選出最貼切的專家身份。若文章橫跨多個領域，選最主要的一個，或組合兩者（例如「資深 C#/.NET 工程師兼系統架構師」）。

| 文章主題 | 評論專家身份 |
|---------|------------|
| C#、.NET、ASP.NET、Entity Framework、LINQ | 專業 C#/.NET 資深工程師 |
| JavaScript、TypeScript、React、Vue、CSS、瀏覽器 | 資深前端工程師 |
| SQL、資料庫設計、索引、Query 優化、Transaction | 資深專業 DBA |
| Docker、Kubernetes、CI/CD、GitOps、雲端架構 | 資深 DevOps 工程師 |
| 系統設計、DDD、Microservices、Clean Architecture | 資深系統架構師 |
| Python、資料科學、Machine Learning、MLOps | 資深資料工程師 |
| 資安、Cryptography、OAuth、Zero Trust | 資深資安工程師 |
| Go、Rust、C、C++、底層系統 | 資深系統程式工程師 |
| 跨語言軟體工程原則（Clean Code、設計模式、測試） | 資深軟體工程師 |

---

### Step 3 — 產生筆記

使用下方模板。重要原則：
- **總結**讓沒看過原文的人也能完全理解核心概念
- **程式範例**每個有程式概念的章節都要有，原文不是 C# 就改寫成 C#，原文沒有就自行補充
- **評論**要有觀點、有批評、有補充，不是複述原文；從業界實戰角度出發

#### 筆記模板

```
# 《[原文標題]》繁體中文總結與評論

> 原文：[標題]

---

## 📋 文章總結

[整體摘要 1-2 段，說明文章想解決什麼問題、核心主張是什麼]

---

### [編號]. [章節標題]（保留英文術語）

[該章節的說明，2-4 句話，著重在「為什麼這件事重要」]

**核心思想**：[一句話精髓]

#### ❌ 錯誤示範

```csharp
// 反例的程式碼（說明為什麼不好）
```

#### ✅ 正確示範

```csharp
// 改善後的程式碼（說明為什麼更好）
```

[重複以上結構至所有章節完成]

---

## 🎯 [專家身份]評論

### 整體評價

[2-3 段，評估文章的定位、適合讀者、核心論點是否站得住腳]

### 值得肯定的地方

[具體指出哪些概念最有價值，結合實務場景說明為什麼]

### 可以更深入的地方

[指出文章哪些地方停留在表面、哪些概念值得延伸或補正]

### 總結評分

| 面向 | 評分 |
|------|------|
| 實用性 | ⭐⭐⭐⭐☆ |
| 深度 | ⭐⭐⭐☆☆ |
| 新穎性 | ⭐⭐⭐☆☆ |
| 適合對象 | [初階 / 中階 / 資深] 工程師 |

**延伸閱讀**：[3-5 本相關書籍或資源，附一句說明]
```

---

### Step 4 — 程式碼範例規則

| 情況 | 做法 |
|------|------|
| 原文是 TypeScript / JavaScript | 改寫成 C# 慣用寫法，不是逐行翻譯 |
| 原文是 Python / Java / Go | 同上，轉成 C# 對應的寫法 |
| 原文已是 C# | 直接保留，若有改善空間可微調 |
| 原文沒有程式碼但有程式概念 | 自行補充最小可運作的 C# 範例 |
| 概念難以用程式碼表達（如 PR 流程） | 用程式碼以外的方式呈現（表格、清單） |

C# 範例要符合現代寫法（C# 10+）：優先使用 `record`、`required`、pattern matching、`sealed`、nullable reference types。

---

### Step 5 — 儲存檔案

1. 確認 `Notes/` 資料夾存在（不存在則建立）
2. 檔案命名：`[文章關鍵字] - 繁體中文總結與評論.md`
   - 取原文標題的主要關鍵字，保持簡短有識別性
   - 範例：`Clean Code Chapter 2 - 繁體中文總結與評論.md`
3. 建立檔案並寫入內容
4. 回覆使用者：告知檔案路徑，並用 1-2 句話描述這篇文章的核心主張

---

## 品質檢查清單

完成後自我檢查：
- [ ] 每個章節都有繁中說明，不只是翻譯標題
- [ ] 有程式概念的章節都有 C# 範例
- [ ] 評論段落有具體觀點，不是重複總結
- [ ] 評論使用的是 Step 2 選定的專家身份撰寫
- [ ] 檔案已成功儲存至 `Notes/`
